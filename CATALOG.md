# Template catalog

## Inclusion criteria

Add a **template** when all of these are true:

- It is a runnable app a customer would start from.
- It covers a Keycard flow end to end against a real zone.
- It ships a README and a `SPEC.md` that the eval build agent can follow.
- It runs headless in eval, with no person in the loop and no paid third-party
  account that we cannot maintain in CI.
- It uses published Keycard SDKs.
- It is not a near copy of an existing template. A new language for the same
  flow counts; swapping the upstream provider usually does not.

Use a **docs example** for a single call or config block, a flow that needs
a vendor or cloud account eval cannot use (such as Databricks, AWS, Azure,
or SPIRE), or a flow that needs a person to click through.

Use an **SDK test** when the goal is to check SDK behavior with mocks and
the check does not need a real zone.

## Flow definitions

- **MCP server:** Protect an MCP server and its tools with Keycard OAuth.
- **Delegated access:** Exchange an authenticated user's token for a scoped token to act on their behalf.
- **Brokered credentials:** Obtain short-lived credentials from Keycard to call an upstream service without storing its credentials in the app.
- **A2A delegation:** Pass a user's request from one agent to another with a token that preserves the user and the acting agent.
- **Workload identity:** Authenticate a workload as itself using a platform identity or a keypair instead of a shared client secret.
- **Agent frameworks:** Integrate Keycard into an agent framework's tool or request lifecycle.
